fix: the quote path never worked -- three stacked bugs starved every replay

The operator asked whether to explore a new architecture, noting two
comparisons is a thin base. The data said the problem is not the number of
comparison groups: of 110k candidates only 5,959 had any shadow price at all,
and most had 2-5 points -- a 60-minute curve needs ~40. Every comparison we
wanted to run was starved by the same hole, and the hole had three layers:

1. mark_from_tokens only re-marked candidates still in the current scan. A
   candidate that dropped out of the ranking had its price history frozen at
   its last in-universe price. Orphaned candidates are now quoted from
   Jupiter (oldest gap first, 60 per round), so a curve survives the token
   leaving the ranking.

2. quote_mints pointed at quote-api.jup.ag/price/v3. quote-api.jup.ag is the
   QUOTE host and 404s on /price; the price API is api.jup.ag (lite-api
   answers too).

3. The v3 payload names the price usdPrice, and the code read "price"; the
   v3 response also sits at the top level while the code read payload["data"]
   (the v2 shape). Two silent mismatches: every call returned {} and every
   caller treats "no quote" as "unknown", so nothing complained.

Layer 3 had been failing since the quote path was written: this is also why
the first money-flow shadow run reported "D-side samples: 0" -- half the
reason was never the universe overlap, it was a price reader reading the
wrong field.

Verified: quote_mints now returns WSOL ~$100.60 and USDC ~$0.9993; 160 tests
pass. The E loop is restarted on the new code so orphaned candidates start
accumulating real curves from this round on -- that is the sample base the
parameter-grid replay (and any new-architecture shadow) needs.
