fix: bound the socket reads -- a half-open connection held the desk for 35 minutes

The operator's diagnosis was right: unstable network, not a dead process. The
evidence was in the ledger: run 807 started, wrote its SEARCH/RISK/GMGN steps,
then sat on JUDGE for 35 minutes with no finish. The network had not dropped
the connection -- it had gone half-open, and urlopen's timeout parameter only
covers CONNECTING. resp.read() on a socket that accepted the request and then
stopped talking blocks until the OS gives up, which on Windows can be tens of
minutes. Every "the loop died" episode today was this: a loop waiting on a
read that had no deadline.

Three modules now set socket.setdefaulttimeout, which bounds every later
socket operation including reads:

  research/memehunter.py        30s  (the Jupiter scans)
  research/pipeline/judge.py    60s  (the StepFun calls)
  research/copywatch/sources.py 30s  (the GeckoTerminal polls)

judge_token also carries a wall-clock budget for the whole call (connect +
read + parse) so a single pathological request cannot eat the round even if
the socket timeout misbehaves.

Verified: runs 820/821/822 completed back to back with all six agents after
the restart, where run 807 had hung on JUDGE for 35 minutes. The live desk
(E) and the follow desk (D) are both running on the new code.

160 tests pass.
