# Replay Engine V1（离线历史回放引擎）

回答一个问题：**规则策略在扣除成本后，能不能在它没参与调参的时间段里持续正期望？**

不训练模型、不接入真实下单。所有结论只来自已记录的数据。

## 为什么需要它

E 的六个 agent 全是确定性规则，没有预测能力；D 的干净回放曾显示扣费后 0/34 钱包正期望。
在把任何一个假设（"成本太高"、"TIMEOUT 太多"、"选币不行"）当成结论之前，需要可复现的证据链。

## 三个部件

### 1. 候选快照（已存在）

`candidates` 表记录每一轮的完整快照：价格、流动性、FDV、`organic_score`、持币数与集中度、
5m/1h/24h 涨跌、净买入地址、当时的 veto 判决与分数。**被 RISK 拒绝的也记录**——否则无法
检验风控过滤掉了什么。

SEARCH agent 现在会写入这张表（此前 pipeline 不落库，只有旧 CLI 写，导致表停更 2 小时——
`research/memehunter.record_candidates()` 是两个入口共用的路径）。

### 2. 影子价格标注（新增，只从现在开始）

`candidate_marks` 表记录候选出现之后的价格。规则：

- **不补造历史**。没有后续价格的候选，回报就是 unknown，绝不插值、绝不用旧价顶替。
- **零额外 API 成本**：SEARCH 每轮已经拉全市场价格，`mark_from_tokens()` 直接复用。
- eligible 候选全标；被拒候选按 mint 哈希确定性 1/10 抽样（可复现），
  这样"风控扔掉了什么"也能被审计。

### 3. 回放引擎（新增，只读）

`research/replay/engine.py` 按 scan 时间序重放：

- 用 candidates 表里**当时记录的** eligible/score/price，不用今天的代码重算（那会改写历史）。
- 退出只用 `candidate_marks` 里**时间戳 ≤ 当前模拟时钟**的价格。上界是硬保证：
  单元测试 `test_replay_never_reads_a_mark_from_the_future` 专门守这条。
- 手续费、滑点（按当时流动性算）、超时、移动止盈全部按实盘口径，成本 bps 可配置。
- 数据末尾仍持仓的仓位只报告、不计入统计。

## 报告

```
python -m research.replay labels   # 一轮影子标注
python -m research.replay replay   # 回放 + 报告
python -m research.replay cost     # 成本敏感性（0/60/120/240 bps）
```

报告第一行永远是**标注覆盖度**（多少个候选有后续价格）。有后续价格的 eligible 候选不足 20 个时
明确标注"结论只是方向性的"。

输出：净收益、单笔期望、胜率、盈亏比、最大回撤、TIMEOUT 占比、平均持仓、退出原因分布，
以及按时间 70/30 划分的开发集/独立测试集（**不随机打乱时间序列**）。

## 已固定的判断口径

- **120bps 不等于结构性亏损**。`cost` 命令测 0/60/120/240 四档；只在 0bps 下成立的规则
  不是 edge，是手续费补贴。
- **TIMEOUT 占比高不等于没有动量**。报告把退出原因分开列，入场晚/止盈目标不合理/退出规则缺陷
  要分开看，不能一锅端。
- **E 与 C 是同池不同规则**（都在 Jupiter universe 里选），对比有效；D 是另一套数据源，
  不与 E/C 同口径比较。

## 当前状态（首日）

标注覆盖 0.03%（影子采集刚启动）。回放引擎本身已用 7 个单元测试锁住不变量：
不读未来、成本单调、时间划分不随机、收益只报有标注的 horizon、报告先报覆盖度。

等 eligible 候选的 5m/15m/30m/1h 标注攒够（预计数天），第一份有统计意义的报告才能出来。
在那之前，任何"策略行不行"的说法都是猜测。
