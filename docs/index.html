The Problem

01市面服务只会「画曲线」，我们负责回答曲线是不是幻觉

每个卖机器人的仓库都有一条漂亮曲线。行业实测：22 个零售 bot 里 17 个与指数相关性 > 0.8——牛市里随机入场也赚钱，这条曲线卖的是 beta，包装成 alpha。样本内过拟合是回测失效的第一死因，而绝大多数回测工具对此一言不发。

我们的立场：这个工具杀死策略，不生产策略。如果你的回测是真的，这份报告是你最好的营销资产；如果它是幻觉，你省下的是一整年订阅费。我们同时披露仪器的边界——报告固定含「未建模事项」一节，未被证伪 ≠ 被证实。
Instruments

02六台仪器，一个裁决

全部规则事前声明：证伪阈值写死在 spec 里、先于结果存在；跑完不分好坏全部发布。

#1Path-aware 回放

同一批信号逐 bar 走价，bar 内止损/止盈同触默认判止损，最坏/最好口径并列——你赚的是价差还是假设？实测过同一信号差 3.5 倍。

#2成本敏感性

费率 ×1 / ×2 / ×5 重放：edge 付不付得起自己的 toll？费率翻倍就翻车的曲线，是在给交易所打工。

#3障碍可达性

止盈/止损位在持仓窗口内到底被摸到过几次——还是止损从未工作的彩票结构？

#4随机入场对照组

同币、同时刻、同退出规则、同成本，随机 bar 入场（固定 seed 可复现）。打不过抛硬币的策略，绝对收益数字没有意义。

#5Walk-forward

窗口切 N 折，样本内/样本外各跑完整电池，同一批事前规则在样本外复判——样本外被证伪 → 整体 FALSIFIED。只在看得见的地方成立的 edge 不是 edge。

#6参数敏感性网格

事前声明的退出参数全网格重放：只有个别格子为正 → 打过拟合标记。edge 只在一小撮参数组合下存在，是曲线拟合不是 edge。

Skill Integration

06作为 Skill 集成：输入一份 spec，输出一份证伪报告

整台引擎是一条命令、一个 JSON 契约——可以被 agent、工作流、CI 直接调用，没有人在回路，也能拿到同一台仪器的裁决。证伪规则先于数字写进 spec，跑完不分好坏全部输出。

输入 · strategy spec（JSON）
{
  "symbol": "BTCUSDT", "interval": "1h",
  "exit": { "take_profit": 0.03, "stop_loss": -0.08,
            "timeout_bars": 24 },
  "fee_rate": 0.0004, "fill_model": "taker",
  "signals": { "kind": "rule", "rule": "rsi_below",
               "period": 14, "threshold": 30.0 },
  "control": { "enabled": true, "n_random": 200, "seed": 42 },
  "falsify_if": {
    "worst_case_net_negative": true,
    "net_negative_at_fee_multiple": 2,
    "control_lift_ci_includes_zero": true
  }
}
spec 结构见 docs/cases/*.json；信号可以是内置规则、CSV 文件，或你的 agent 自己生成的入场列表。
$ python -m research.verify --spec spec.json --candles klines.csv --signals sig.csv --out report.md --json
输出 · falsification report（markdown + JSON 双格式）
· verdict：FALSIFIED / UNPROVEN / INCONCLUSIVE
· 六维结果：回放 / 成本 / 障碍 / 对照 / walk-forward / 网格
· 事前证伪规则逐条判定 + 未建模事项披露

本地离线可跑，无外部依赖；样本不足时输出 INCONCLUSIVE，永不放过。机器可读的 JSON 直接进你的流水线，markdown 直接给人看。
